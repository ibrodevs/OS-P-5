## Формат входных данных

Каждая строка описывает процесс:

```text
PID arrival burst priority
```

Пример:

```text
P1 0 8 3
P2 1 4 1
P3 2 9 4
P4 3 5 2
```

Для Priority меньшее число означает более высокий приоритет.

## Выполнение задания

### 1. FCFS

**First Come, First Served** выполняет процессы в порядке поступления. Алгоритм прост и не вытесняет уже запущенный процесс.

Преимущество — минимальная сложность. Недостаток — длинный процесс может задержать все следующие процессы, что приводит к convoy effect.

### 2. SJF

**Shortest Job First** выбирает среди уже прибывших процессов тот, у которого минимальный `burst`.

Алгоритм может уменьшать среднее время ожидания, но требует знания или оценки длительности CPU burst.

### 3. SRTF

**Shortest Remaining Time First** — вытесняющая версия SJF. При появлении нового процесса симулятор сравнивает оставшееся время и при необходимости вытесняет текущий процесс.

Для контрольного `set1` получено:

```text
Average waiting time = 6.50
Average turnaround   = 13.00
```

### 4. Priority Scheduling

Реализовано вытесняющее планирование по приоритету. Если приходит процесс с более высоким приоритетом, текущий процесс может быть вытеснен.

Проблема такого алгоритма — **starvation**: низкоприоритетный процесс может долго не получать CPU, если постоянно приходят более приоритетные задачи.

### 5. Aging

Для борьбы с starvation реализован aging. По мере ожидания приоритет процесса постепенно улучшается.

Таким образом, даже процесс с изначально низким приоритетом со временем получает возможность быть выбранным планировщиком.

### 6. Round Robin

Round Robin использует циклическую очередь и квант времени `q`.

Пример:

```bash
python3 sched.py --algo rr --quantum 3 set1.txt
```

Для `q = 3` на контрольном наборе:

```text
Average waiting time = 13.50
Average turnaround   = 20.00
```

Малый квант улучшает отзывчивость, но увеличивает число переключений контекста. Большой квант уменьшает overhead, но постепенно приближает Round Robin к FCFS.

### 7. Исследование кванта `q = 1..10`

Для `set2.txt` выполнен эксперимент с квантами от 1 до 10. В `rr_quantum.svg` показаны:

- среднее время ожидания;
- число переключений контекста.

График демонстрирует компромисс: увеличение кванта уменьшает число переключений, но влияет на задержки и отзывчивость.

## Используемые метрики

Для каждого процесса вычисляются:

```text
turnaround = completion - arrival
waiting    = turnaround - burst
response   = first_start - arrival
```

Также рассчитываются:

- среднее время ожидания;
- средний turnaround;
- среднее время отклика;
- загрузка CPU;
- количество переключений контекста.

## Вывод

Алгоритмы планирования оптимизируют разные характеристики системы. FCFS прост, SJF/SRTF способны уменьшать среднее ожидание, Priority позволяет учитывать важность задач, но может приводить к starvation, который уменьшается с помощью aging. Round Robin обеспечивает более справедливое распределение процессорного времени и хорошую отзывчивость, однако слишком маленький квант увеличивает количество переключений контекста. Поэтому выбор алгоритма зависит от целей конкретной системы.
